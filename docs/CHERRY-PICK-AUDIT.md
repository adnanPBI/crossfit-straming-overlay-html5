# Surgical feature audit — CHALKLINE Grok workspace → WOD Stream Studio 1.1.0

## Audited inputs and decision

- Source baseline: WOD Stream Studio 1.0.0, existing `adnanPBI/crossfit-straming-overlay-html5` `main` commit `97040359646a7e3817c4222996b0551ef695453a`.
- Incoming reference: supplied `crossfit-streaming-grok-workspace.zip` containing a CHALKLINE React/TypeScript/TanStack app, Grok host integrations, server/database abstractions, WebRTC spectator pages, workout timers, control deck and overlay UI.
- Target: the client's self-hosted **HTML5/CSS/JavaScript** application that must work without developer accounts, monthly subscriptions, unrelated external services, or code obfuscation, via **OBS Browser Source → OBS Virtual Camera → Zoom**.
- Method: inspect concepts/components and **reimplement relevant behaviors in the existing native ES module code**; preserve prior storage/auth/timer and 1920×1080 transparency. No repository replacement or copying generated Grok hosting/authentication infrastructure.

## Preserved security and compatibility requirements

1. Original `/overlay` remains read-only, full-HD and transparent by default; the query `?bg=black` or `?bg=green` only changes the backdrop.
2. Every mutating API, including phone remote `/api/timer`, scene load, settings and backup import, requires the persistent random control key (`X-Overlay-Key`); no 8-character room code is a substitute for authentication.
3. Timer state is generated by one server authority and shared unchanged through `/api/state` and `/api/events`. Existing pause, reset, interval timer, scene backup, and SSE semantics remain functional.
4. Old `crossfit-overlay-v1` backups and version-1 settings have backwards-compatible schema defaults; the backup format **does not change** even though application version is 1.1.0.
5. Submitted image URLs only permit validated raster data URLs or the included sample logo. HTML uses `textContent` for user inputs; it does not insert custom HTML in streaming content.
6. No paid licenses or npm runtime dependencies were introduced. Saved application data and generated control key are excluded from git by `.gitignore`.
7. Local OBS/Zoom physical device validation, virtual camera enablement and audio routing must be completed as a separate acceptance test. Browser/headless tests cannot certify that a real Zoom call works.

## Verification and acceptance

Run the built-in suite:

```sh
npm run check
npm test
```

The 1.1.0 suite includes 17 unit and integration tests covering: new formula grammar and rejection cases; AMRAP, EMOM, Tabata and For Time schedules; boundary handling; SVG/injected sponsor rejection; auth-gated rewind; scene export and active ID; existing server state persistence/SSE/auth; language parity for all six locales.

Optional Playwright verification (developer only):

```sh
python tests/ui-offline.py
python tests/visual-qa.py
python tests/remote-ui.py
```

These test DOM interactions through an offline Chromium document harness because this test environment does not permit Chromium to navigate to localhost over HTTP. Inspect real on-device overlay output and Zoom meetings before signoff.

## Self-hosted release usage

1. Run `npm start` and keep the terminal active.
2. Control: `http://localhost:4173/control` (key required); compact phone control: `http://LAN-IP:4173/remote` (same key).
3. OBS browser source: `http://localhost:4173/overlay`, 1920×1080; use this source above camera input.
4. Alternatives: `http://localhost:4173/overlay?bg=black` or `?bg=green` for specific composite/chroma-key workflows.
5. In OBS, Start Virtual Camera; in Zoom, select OBS Virtual Camera. This transfers video, **not sound**; set up and validate a distinct audio path if cues are needed.

## Scope and rights

The existing custom source rights document (`LICENSE-AND-RIGHTS.md`) still governs the released code; imported workspace third-party assets and hosted framework packages were not bundled.
